6.1.12.1. gemini_model.fluid.pvt_config

Project-JSON-settable PVT properties for the well models (GM-01).

GEMINI’s PVTConstantSTP hard-codes fresh water at standard conditions (rho 1000 kg/m3, mu 1e-3 Pa.s, c_p 4217.4 J/kg.K). The design-basis brine is heavier and less viscous (rho 1030 kg/m3, mu 0.40e-3 Pa.s [P, DB-08]; c_p 4100 J/kg.K [A, DB-33]), which adds about 7.4 bar of hydrostatic head over 2.5 km.

This module turns an optional "pvt" block in a component’s project-JSON parameters into a configured PVTConstantSTP. The same block is the single source of truth for the primary-loop liquid density and heat capacity: gemini_simulator.kpi reads it from the producer well, and heat_exchanger_fluid_parameters() gives the matching parameters to set on the heat exchanger, boiler or CHP (the project builder must copy them there; kpi.fluid_consistency_issues reports a mismatch).

A "pvt" block may use the native PVTConstantSTP keys (RHOL, VISL, CPL …) or the unit-suffixed aliases in PVT_PARAMETER_ALIASES. Keys that start with _ are comments and are ignored. An empty or missing block gives exactly the GEMINI defaults.

Source: RC-01 “Inputs” and validation tests (hydrostatic head 252.6 bar for 1030 kg/m3 over 2500 m; 7.36 bar more than water).

Return a fresh PVTConstantSTP with a "pvt" block applied.

gemini_model.fluid.pvt_config.heat_exchanger_fluid_parameters(pvt_parameters=None)[source]

Return the fluid_density/specific_heat parameters for HEX, boiler and CHP.

GEMINI’s HeatExchanger, Boiler and CHP take the liquid density and heat capacity as fluid_density (kg/m3) and specific_heat (J/kg.K) parameters. Use this helper so a component on the brine loop gets the same values as the wells (single source of truth, GM-01). Note that GEMINI’s HeatExchanger applies one fluid_density/specific_heat to both its primary (brine) and secondary (water) sides.

gemini_model.fluid.pvt_config.liquid_properties(pvt_parameters=None)[source]

Return (density_kg_m3, specific_heat_j_kgk) of the liquid phase.

These are the values the well models use for the same "pvt" block; keys the block does not set keep the PVTConstantSTP defaults.
